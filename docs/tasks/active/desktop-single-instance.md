## 目标

Tauri 桌面版同一时间只能运行一个实例。用户再次启动应用时，第二个进程退出，已运行的 `main` 窗口显示、取消最小化并获得焦点。

## 非目标

- 不改变浏览器 `pnpm dev` 的多标签页行为。
- 不实现第二次启动时的文件/深链接参数路由。
- 不修改窗口尺寸、位置持久化或阅读器业务状态。

## 当前现象与证据

- 复现步骤：在 Windows 桌面版已经运行时再次启动可执行文件。
- 根因：当前 Tauri builder 未注册单实例协调机制。

## 必须保持的行为

- 仅桌面目标加载单实例插件；移动端与浏览器开发路径不依赖该插件。
- 单实例插件必须是第一个注册的 Tauri 插件。
- 找不到 `main` 窗口或任一窗口操作失败时，不应使现有实例崩溃。

## 预计修改文件

- `src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`：加入桌面目标限定的官方插件。
- `src-tauri/src/lib.rs`：最先初始化插件并恢复/显示/聚焦主窗口。
- `docs/BUGFIX_LOG.md`、`docs/MODULE_CONTRACTS.md`、`docs/SOURCE_DELTA.md`、本文件：记录稳定行为与验证。

## 实际修改

- `tauri-plugin-single-instance 2.4.3` 以 desktop target cfg 加入 Cargo 清单并锁定。
- 单实例插件在所有其他插件前注册；第二实例通知抵达时，已有 `main` 窗口依次 `show`、`unminimize`、`set_focus`，每一步都容错。
- 新增纯 Rust 回归以固定窗口恢复动作顺序。
