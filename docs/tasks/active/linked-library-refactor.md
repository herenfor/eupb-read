# 任务：链接式书库、可同步存档与有界封面缓存

- 状态：实现与自动化验收完成，待 Windows 发布包验证
- 创建日期：2026-08-20
- 最后更新：2026-08-20
- 目标版本：0.1.7 测试发布候选

## 已确认目标

1. Tauri 桌面版导入后只保存源 EPUB 的本机路径和内容身份，不复制 EPUB 正文。
2. 可同步状态与设备路径彻底分离：跨平台存档以 `contentHash` 关联元数据、进度、书签和设置；绝对路径只存在设备本地索引。
3. SHA-256 在 Rust 侧流式计算；启动不重哈希全部藏书，只以路径、大小和 mtime 做快速检查，变化后才重新确认内容。
4. 批量导入只解析 container/OPF/加密声明/封面定位等必要元数据，不为入架完整解压全书；整批只提交一次 UI/索引。
5. 书架封面只在接近视口时读取，并生成最大约 240×360 的缩略图；并发上限 4、磁盘 LRU 上限默认 100 MiB。缩略图可再生、不进入同步存档。
6. 删除书架条目只删除状态、路径映射和缩略图，绝不删除源 EPUB；源文件缺失时保留存档记录并允许重新定位。
7. 阅读进度继续保证最后稳定位置胜出；快速翻页合并，返回书架、隐藏和正常关闭时 flush。存档导出不得包含设备绝对路径。
8. 书架渲染成本由可见卡片数量决定；隔离只在阅读界面需要的时钟更新，避免 100+ 卡片空闲重渲染。

## 数据边界

- `LibraryRecord`（可同步）：`contentHash`、书名/作者/文件名提示、添加/最近阅读时间、章节/页码/百分比/锚点、书签、`isNew`。
- `DeviceBinding`（不得同步）：`contentHash`、规范化源路径、文件大小、mtime、封面 ZIP 路径与媒体类型、最近一次验证时间。
- `Thumbnail`（可删除缓存）：以 `contentHash` 命名，保存派生图片及访问时间；任何缺失都可从绑定的 EPUB 重建。

## 必须保持

- 精确重复继续以完整 EPUB 字节 SHA-256 判断；文件名变化不影响识别。
- 同内容重新定位、重命名或重新导入不得覆盖进度、书签和首次添加时间。
- 源文件内容改变后不得静默套用旧内容身份；旧记录保留为缺失绑定，除非用户明确处理。
- EPUB 源路径由 Rust 后端规范化、校验和使用；存档读写只接受系统 dialog 动态授权的路径，前端不能以存档内容指定任意目标路径。
- 浏览器 `pnpm dev` 只是隔离测试后端；真实持久路径契约以 Tauri 为准。

## 明确不做

- 本轮不迁移 0.1.6 测试书库；切换后清理旧 Roaming/Local 与 WSL 测试存储。
- 不实现云服务或多设备同时写入冲突合并，只提供稳定的单文件存档导入/导出边界。
- 不把源 EPUB、封面原图或缩略图放进同步存档。
- 不处理“单个 EPUB 达到 10GB”的随机访问渲染；本轮目标是总藏书十几 GB 时不产生正文副本。

## 并行实施边界

- Rust 后端：链接路径、流式哈希、轻量 ZIP 元数据、索引原子提交、封面条目读取与缓存文件命令。
- 封面/UI：视口门控、四并发队列、缩略图生成、Blob 生命周期、卡片渲染隔离。
- 存档/进度：同步 schema、设备路径排除、导入导出校验、合并/flush 纯逻辑。
- `App.tsx`、`ShelfStore` 最终接口和跨模块集成由主代理统一完成，子任务不得自行改变其他层契约。

## 验收

- 100 本导入后应用数据目录没有 EPUB 正文副本。
- 重启不读取/哈希每本 EPUB；书架只加载视口附近封面，缩略图缓存不超过 100 MiB。
- 进度、书签、重复识别、缺失文件提示和重新定位均有自动化回归。
- 导出的存档逐字段检查不含 Windows/Linux/macOS 绝对路径。
- 删除条目与卸载不会删除用户源文件；临时/缩略图缓存可完整清理。

## 已完成实现

- 新增 Rust 链接书库后端：批量路径导入、流式 SHA-256、受限 ZIP 元数据读取、缺失/变更源文件检测、同哈希重新定位、进度/书签/新书状态写回，以及缩略图缓存读写。
- 桌面运行时不再注册旧复制式 `shelf.json`、正文和封面托管命令；桌面导入只保存可同步记录与设备绑定。浏览器 IndexedDB 继续作为 `pnpm dev` 的隔离测试后端。
- 新增版本 1 的 JSON 存档导入/导出。导出只含可同步记录和安全设置；导入按 `contentHash` 合并较新的进度/书签，不携带源路径、正文、封面原图或缩略图。
- 新增接近视口才工作的封面缩略图管线：最大 240×360、全局最多 4 个并发任务、单项不超过 5 MiB、设备缓存总量不超过 100 MiB。书架卡片 memo 化，并使用 `content-visibility` 隔离离屏布局。
- 进度写入器改为每本书的首次稳定值立即提交、后续 750 ms 合并；在途写入不会吞掉更新值，返回书架、页面隐藏和正常关闭时统一 flush。
- 缺失源文件的记录继续保留；点击后可选择新路径重新关联，只有完整字节哈希一致才接受。删除书架条目只清除记录、绑定和缩略图。
- 桌面文件选择和存档保存/读取使用 Tauri dialog/fs 插件；路径由系统选择器产生，Rust 后端仍负责源文件与哈希校验。

## 已知边界

- 单本书打开时仍需把 EPUB 正文交给现有前端解析器；本轮解决的是“总书库十几 GB 不复制、不在启动时全量读取”，不是单个 10GB EPUB 的随机访问阅读。
- `library-records.json` 与 `device-bindings.json` 在同一进程写锁内分别使用临时文件原子替换。普通文件系统无法让两个独立 JSON 形成真正的跨文件原子事务；极窄崩溃窗口下，缺失或孤立绑定会被视为不可用，记录本身仍可从存档恢复。
