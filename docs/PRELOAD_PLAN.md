# 渲染显示与章节预加载规划（P0/P1 已实现，P2 预留）

> 状态：P0 已实现；2026-08-23 完成 P1a 下一章单槽及 P1b 前后相邻三槽预渲染，P2 动画仍未实施。
> 目标：① 消除“首次进入章节时图片从居中跳到对齐”的中间帧；② 为移动端翻页动画准备章节/页级预加载。

## 1. 问题定义

1. 章节第一次加载时，默认居中规则先渲染一帧，第二遍 margin 修正后才跳到正确位置；后续同章内图片正常。
2. 未来移动端需要平滑的翻页动画；当前“翻页=替换章节 DOM/跳 scrollLeft”，没有预渲染，动画会出现空白。

## 2. 目标与非目标

**目标**
- 章节 ready 前不显示未修正的中间状态；
- 预加载当前章前后相邻章（范围待拍板），翻页时可立即/快速切换；
- 为 Android 触摸翻页与滑动动画预留接口；
- 内存可控、可失效重建（字号/窗口/主题变化）。

**非目标**
- 不做全书预加载；
- 不在本轮做真正的动画实现（只做预加载基础）；
- 不做 CFI/高亮等无关功能。

## 3. 当前架构约束

- 一次只渲染一个 `ReaderView`，内部单 iframe + 单 `ChapterPaginator`；
- `ChapterPaginator.load()`：sanitize → blob → 字体 ready → 测量 → margin/fit/float 第二遍修正 → recompute；
- 章节切换由 App 改 `spineIndex` 触发 effect；
- 阅读位置（页码/锚点）在 App 层持久化；
- 窗口/设置变化通过 `reflow` 和 `reloadWithSettings` 重新布局。

## 4. 方案总览

### P0：首帧稳定性（已实现，B-015）
- `VisibilityGate` 在 load 开始、blob 导航和 iframe load 三个边界保持 iframe 为 `visibility:hidden!important`；不使用会阻断布局的 `display:none`。
- 显示门 token 与 `loadSeq` 同步转交，旧章节异步完成不能揭示新章；原有 inline visibility、错误、20 秒兜底超时和 dispose 均可恢复。
- `prepareChapterForDisplay()` 把“字体/双 rAF → fit-content/margin/float 二阶段补偿 → 可等待的 recompute 自愈 → 目录锚点或章末定位”固定为同一 ready 顺序，完成后才揭示。
- `recompute()` 已改为可等待内部最多两次布局自愈；以后预加载器可复用这条准备顺序，不需要猜测页数是否稳定。
- 记录最近一次完整测量的 iframe 尺寸，过滤组件挂载产生的同尺寸 `ResizeObserver` 空转；否则揭示后仍会短暂撤销布局补偿并再次闪动。
- B-016 补充 display-ready 交互边界：hidden iframe 不命中 wheel 时由外层阅读区接收，加载期间只保存最后一个翻页方向；最终揭示后消费一次。浏览器可能把整段连续滚轮锁定在外层目标，因此 ready 后外层仍按 80px 阈值继续翻页，避免固定停在第 2/倒数第 2 页。
- 验证：真实 EPUB 简介页逐帧记录显示，错误中间位置只出现在 hidden 帧，首个可见帧与最终布局完全一致；从第二章回翻时首个可见帧即上一章第 10/10 页；多视口、字号、`:target` 与表单状态整书回归通过。

### P1：章节级预加载（移动端翻页动画的基础）
- 范围：默认当前章 + 前 1 章 + 后 1 章（**拍板**）；
- 结构：`ChapterPreloader` 管理一个离屏 iframe 池（复用 `ChapterPaginator`，尺寸与主 iframe 一致）：
  - 离屏但可布局（`left:-9999px` 等，不能 display:none）；
  - 按路径 key 缓存已准备章，LRU 上限 3；
  - 优先级：当前章 > 后一章 > 前一章；
  - 目录跳转不可预测：不做预取，跳转目标进入“按需加载 + P0 显示门”路径；
- 准备完成判定：字体 ready + 分页完成 + margin 修正完成 + 目标页码/锚点定位完成；
- 失效机制：字号/窗口宽度/主题/设置变化时清空池；图片 load 事件继续现有 reflow；
- 生命周期：切书、关闭书时 revoke 所有 blob、移除 iframe；
- 配置：缓存章数、预加载开关（移动端默认开，桌面默认可先关）。

### P1a/P1b：相邻章节三槽（已实现，B-061/C-50）

- 桌面菜单提供默认关闭的“高性能模式”；fixed-layout 禁用。
- 标准模式只有当前 iframe；开启后最多为上一篇、当前篇、下一篇三个同尺寸 iframe。
- 后台分页器复用完整 display-ready 边界，构造回调按 active slot 身份静默门控。
- React 已提交目标 spineIndex 后才提升 ready 槽位；未命中、失败、跨越跳转继续走 P0。
- 开关仅影响调度，不重载当前章；实际渲染设置/字体/尺寸变化销毁旧预载。
- 后台严格先准备下一篇 linear 章节、完成后再准备上一篇，避免两个隐藏分页任务并发；提升后旧当前章成为反向缓存。
- 显式目录/搜索/书签/笔记/历史跳转不提升相邻缓存，未命中仍走 P0；设置/字体/尺寸变化释放全部备用槽。

### P2：页级过渡与动画接口（后续）
- 同章翻页：
  - 当前列 + 相邻列已经存在于同一 DOM，预渲染不是问题；
  - 动画可用 scrollLeft 过渡（PC 可保持瞬切，移动端用位移动画）；
- 跨章翻页：
  - 用两个已准备 iframe 做左右滑动（或单 iframe 动画 + 备用章）；
  - 动画时长/曲线需拍板；
- 只为 App 层定义 `transitionTo(page | chapter)` 接口，不在本轮实现动画。

## 5. 关键技术点与风险

- **离屏 iframe 测量**：不能 display:none；尺寸必须与主阅读区完全一致，否则分页页数不同；
- **第二遍修正必须进入 ready 判定**：预加载完成的章也要完成 margin/fit/float 修正；
- **内存**：每章 blob + 图片解码，Android 上必须限制缓存章数并做 LRU；
- **窗口/设置失效**：resize、字号、主题变化会导致所有预热失效，需要防抖后重建；
- **快速连翻**：预加载永远可能追不上，P0 显示门仍是最后兜底；
- **回翻/进度恢复**：恢复页码、锚点、`startAtEnd` 都要在预加载完成后定位，再交给界面显示。
