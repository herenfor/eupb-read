# 从正文搜索到 RAG 的开发方向

## 文档状态

- 性质：长期能力路线与后续分支的范围基线。
- 当前状态：已完成技术调研，并完成 B-059/C-48 的当前书基础正文搜索切片；跨书、持久化索引、语义检索、标签、RAG 等仍未实现，也不代表已进入稳定发布范围。
- 当前平台重点：先研究 Windows 桌面端；Android 只保留未来扩展方向。
- 阶段实现目标：跨书全文检索、语义检索、相似内容、建议标签和智能分类。
- 最终目标：在可靠检索与原文锚点之上，实现带引用的 AI 问答和分层正文总结。

本文所说的 RAG 不是单一“聊天模型功能”。搜索、语义向量、分类、生成分别是可替换的层；没有生成模型时，全文检索、语义搜索和固定体系标签仍应独立可用。

## 总体边界

```text
EPUB 源文件
  → 结构化正文语料
  → 稳定章节/文本锚点
  ├─ SQLite FTS → 全文搜索
  ├─ EmbeddingProvider → 语义向量
  ├─ VectorStore/Retriever → 相似内容与跨书检索
  ├─ TaggingService → 建议标签与智能分类
  └─ GeneratorProvider → RAG 问答与正文总结（最终阶段）
```

必须保持以下边界：

- 阅读器核心不能依赖生成模型才能打开、搜索或阅读书籍。
- 索引和向量属于可删除、可重建的本机缓存，不进入阅读进度存档。
- 用户标签、用户确认的 AI 标签和用户编辑过的摘要属于可同步数据。
- 嵌入模型与生成模型分别配置；更换生成模型不得触发全库向量重建。
- 模型供应商可替换，不绑定 OpenAI、Ollama 或单一下载平台。
- AI 结果必须能回溯到书名、章节、正文块和稳定锚点。

## 第一阶段：结构化正文语料

当前完成的是搜索所需的会话级最小语料层，不是完整的持久化语料仓：按当前书 spine 按需提取可见正文，保留章节路径/标题、原文范围与现有文本锚点，并进行标准化映射。切块版本、书籍指纹、派生数据失效和持久化语料仍待后续实现。

- [x] 按 EPUB spine 顺序提取正文（当前书、按需、会话级缓存）。
- [x] 保留章节标题、章节顺序和章节路径（书名/作者元数据及内容类型分层仍待完善）。
- [ ] 将正文、目录、版权页、注释和脚注区分或标记。
- [ ] 按标题、段落和句子边界切块，避免任意截断句子。
- [ ] 相邻正文块保留少量可配置重叠。
- [ ] 每个正文块具有稳定 ID、章节路径、顺序和原文锚点。
- [x] 同时保存原始文本、标准化文本和二者的位置映射（仅当前会话，不持久化）。
- [x] 标准化大小写、全半角（NFKC）、异常空白、换行和软连字符。
- [ ] 用书籍指纹检测源 EPUB 内容变化。
- [ ] 书籍删除、变更或重新定位时正确失效对应派生数据。
- [ ] 解析器、标准化器和切块器均有独立版本号。

## 第二阶段：基础全文搜索

此阶段不需要任何 AI 模型。B-059/C-48 已完成带“当前书”标记的条目；未标记项目仍未实现。

- [x] 当前书正文搜索（按需、可取消、会话级缓存）。
- [ ] 跨书全文搜索。
- [x] 标准化完整短语和同上下文多关键词 AND 搜索；OR、前缀和邻近搜索未实现。
- [ ] 按书名、作者、章节、内容类型和标签过滤。
- [ ] 三字及以上可使用 SQLite FTS5 trigram 召回。
- [ ] 一至二字查询使用单独的短查询路径。
- [x] 以标准化子串匹配并保留原文范围，避免标准化结果错误高亮。
- [x] 显示章节、上下文片段和真实命中高亮（当前书，不显示跨书书名列）。
- [x] 点击结果通过现有稳定文本锚点跳回原文。
- [x] 支持取消；上一条/下一条结果和搜索历史仍待实现。
- [x] 搜索预览不改变阅读进度，点击跳转才进入既有阅读历史。
- [x] 分章处理主动让出 WebView 主线程；跨书调度和持久化索引仍待后续评估。

## 第三阶段：模型和下载管理

- [ ] 建立独立 `EmbeddingProvider`、`GeneratorProvider` 和可选 `RerankProvider`。
- [ ] 嵌入模型支持内置 ONNX Runtime。
- [ ] 支持 Ollama 嵌入/生成模型作为高级用户选项。
- [ ] 支持本地 GGUF 生成模型和本地 ONNX 嵌入模型导入。
- [ ] 预留 OpenAI-compatible 与其他厂商 API。
- [ ] 国内网络不能依赖 GitHub、Hugging Face 或微软服务器作为唯一来源。
- [ ] 支持项目国内源、ModelScope、备用地址和用户自定义源。
- [ ] 提供基础版（不含模型）与可选 AI 完整版（内置轻量嵌入模型）的分发空间。
- [ ] 下载支持暂停、继续、HTTP Range、临时文件和应用重启恢复。
- [ ] 下载前检查磁盘，完成后校验 SHA-256 并原子替换。
- [ ] 展示模型大小、用途、设备要求、许可证与原始来源。
- [ ] 支持离线导入、重新定位、删除模型和清理缓存。
- [ ] 模型清单记录 provider、model ID、版本、digest、格式和向量维度。

统一接口方向：

```text
EmbeddingProvider.embed(texts) → vectors
GeneratorProvider.generate(prompt, context) → token stream
RerankProvider.rerank(query, chunks) → scores
```

## 第四阶段：语义索引

- [ ] 批量生成正文块向量，模型只加载一次并使用批处理。
- [ ] 保存正文块、向量和模型身份的对应关系。
- [ ] 评估 Float32、Float16 与 Int8 的质量、速度和空间。
- [ ] 支持单本、增量和全库建库。
- [ ] 支持暂停、继续、取消、失败重试和应用重启恢复。
- [ ] 单本失败不得使整库事务失败。
- [ ] 阅读期间降低或暂停后台任务，限制线程、CPU和内存。
- [ ] 显示书籍级与全库级进度。
- [ ] 支持重新索引单本、全部重建和一键清理。
- [ ] 模型、模型 digest、维度或切块版本变化时只失效对应索引。
- [ ] 初期优先精确余弦检索；规模实测需要后再引入近似索引。
- [ ] 向量存储通过适配层接入，不能让持久格式永久绑定 pre-v1 扩展。

索引身份至少包含：

```text
bookFingerprint
parserVersion
normalizerVersion
chunkerVersion
embeddingProvider
embeddingModelId
embeddingModelDigest
dimensions
```

## 第五阶段：智能检索（主要实现目标）

- [ ] 当前书和跨书语义搜索。
- [ ] 自然语言描述搜索。
- [ ] 在模型支持时提供跨语言检索。
- [ ] 查找相似段落、相似章节和相似书籍。
- [ ] 从当前阅读位置寻找相关内容。
- [ ] 关键词检索与向量检索并行。
- [ ] 使用 RRF 或经评测确认的方式融合结果。
- [ ] 人名、术语和原句查询提高关键词权重。
- [ ] 描述性问题提高语义结果权重。
- [ ] 支持书籍、作者、标签和范围过滤。
- [ ] 显示相关度、召回方式、书名、章节和原文片段。
- [ ] 点击结果可靠跳转至原文锚点。
- [ ] 无嵌入模型或模型不可用时自动降级为全文搜索。
- [ ] 允许用户反馈相关/不相关，为离线评测保留数据边界。

## 第六阶段：标签与智能分类（主要实现目标）

### 用户标签

- [ ] 创建、重命名、删除、分组、着色和组合筛选。
- [ ] 一个书籍支持多个标签。
- [ ] 用户标签始终优先，AI不得静默覆盖。
- [ ] 用户标签和用户确认结果可进入同步存档。

### 固定标签体系

- [ ] 按场景、题材、风格、人物等维度建立标签体系。
- [ ] 每个标签保存名称、说明、父级、同义词和体系版本。
- [ ] 支持互斥、包含和共存规则。
- [ ] 标签说明可以生成向量并与书籍内容比较。

### 建议标签

- [ ] 先以规则、元数据和标签向量相似度生成候选。
- [ ] 输出置信度并区分书级与章节级标签。
- [ ] 每个建议保存证据正文块，点击可以回到原文。
- [ ] AI结果初始为 suggested，用户确认后才成为正式标签。
- [ ] 用户可以拒绝建议，拒绝结果不会反复出现。
- [ ] 重新计算不得覆盖用户确认、拒绝或手工修改。
- [ ] 生成式模型存在时可复核候选，但不作为基础分类的依赖。

### 智能书架与推荐

- [ ] 根据单个或多个标签建立动态书架。
- [ ] 根据内容向量生成相似作品和主题聚类。
- [ ] 根据用户选定的参考书寻找相似书籍。
- [ ] 展示推荐依据，允许关闭或删除智能规则。

## 第七阶段：检索质量与性能评测

- [ ] 建立固定问题、正确书籍、章节和正文块组成的测试集。
- [ ] 分别测量全文、向量和混合检索的 Recall@K、MRR/nDCG。
- [ ] 比较切块长度、重叠、模型、量化方式和 Top-K。
- [ ] 覆盖中文、日文、英文、跨语言、人名、虚构术语和短查询。
- [ ] 覆盖错字、近义表达、同义词和原句搜索。
- [ ] 测量单本/百本书建库时间、查询延迟、峰值内存和磁盘占用。
- [ ] 检索算法修改必须通过固定评测，不只依靠主观观察。

进入生成阶段前，智能检索和引用跳转必须已经稳定；生成模型不能掩盖召回错误。

## 第八阶段：生成式模型运行层

- [ ] Windows 默认可采用应用内置 llama.cpp sidecar，按需启动和停止。
- [ ] CPU路径始终可用，GPU加速是可选能力而不是基本要求。
- [ ] 支持用户选择本地 GGUF、Ollama、局域网服务或远程 API。
- [ ] 生成模型与嵌入模型分别配置和展示。
- [ ] 按设备内存、显存和模型大小给出提示。
- [ ] 模型按需加载，空闲后卸载；生成支持流式输出和取消。
- [ ] sidecar 使用临时端口/鉴权或其他受控 IPC，不暴露局域网。
- [ ] 子进程崩溃不能带走阅读器，应用退出必须回收进程。
- [ ] 更换生成模型不重建向量索引。
- [ ] 远程调用前明确展示发送范围和隐私影响。

## 第九阶段：带引用的 RAG 问答

- [ ] 支持当前章节、当前书、选定书籍和全书库四种范围。
- [ ] 使用混合检索召回原文，去除重复片段并控制上下文预算。
- [ ] 保留书籍和章节边界，避免跨书错误归因。
- [ ] 回答必须附带书名、章节、正文块和原文锚点引用。
- [ ] 点击引用回到原文，并明确区分模型回答与原文。
- [ ] 证据不足时允许拒答，不要求模型强行生成。
- [ ] 支持多轮追问，但限制会话上下文增长。
- [ ] 问答历史可保存、导出和删除。
- [ ] 无生成模型时降级为“问题 → 相关原文”，不伪装成完整回答。

## 第十阶段：AI 正文总结（最终目标）

总结必须分层完成，不能把整本书无条件一次性交给模型：

```text
正文块摘要
  → 章节摘要
  → 分卷摘要
  → 全书摘要
```

- [ ] 生成章节摘要并保存来源正文块。
- [ ] 支持无剧透简介和完整剧情总结两种模式。
- [ ] 生成人物、地点、组织、重要事件和时间线。
- [ ] 生成人物关系、主题、风格和内容警告建议。
- [ ] 开放式标签只能作为建议，并保留证据。
- [ ] 每一层摘要记录模型、提示词、算法和来源版本。
- [ ] 支持暂停、继续、取消、失败恢复和后台运行。
- [ ] 中间摘要可复用，修改最终提示词不必重算底层正文。
- [ ] 用户可以编辑摘要；用户版本与 AI 原始版本分开保存。
- [ ] 更换模型可以保留旧结果并比较，不静默覆盖。
- [ ] 阅读期间限制总结任务的CPU、内存和显存使用。

## 数据同步与隐私

- [ ] 阅读进度、书签等核心存档不依赖索引数据库。
- [ ] 正文副本、全文索引、向量和模型文件默认不进入同步存档。
- [ ] 用户标签、确认标签和用户编辑摘要可以同步。
- [ ] AI原始结果是否同步由用户决定。
- [ ] 删除书籍时清理其索引、问答和摘要派生数据。
- [ ] 提供清除全部 AI 数据和模型的入口。
- [ ] 本地推理不上传正文。
- [ ] 远程推理按当前章节/当前书/选定范围最小化发送内容。
- [ ] 模型文件、下载源和模型许可证分别审计。

## 性能和平台策略

Windows 第一阶段以 CPU 为基础路径：全文与向量查询不要求独立显卡；GPU主要加速大批量建库和生成式模型。后台任务必须服从阅读优先级。Android 后续优先移植全文搜索和已生成分类结果，再评估量化嵌入模型；本地生成式模型不作为手机基础功能。

建议提供：

- 基础版：不含模型，全文搜索始终可用。
- AI完整版：在许可证允许时内置轻量量化嵌入模型。
- 生成模型：国内源下载、本地 GGUF、Ollama 或远程 API，不进入主安装包。
- 所有模型：支持离线导入和重新定位。

## 推荐开发顺序

```text
1. 正文语料与稳定锚点
2. SQLite FTS5 与结果跳转
3. 模型管理、国内下载和离线导入
4. 嵌入模型与可恢复语义索引
5. 混合检索、相似内容和评测
6. 标签体系、建议标签和智能书架
7. 生成模型 Provider
8. 带引用的 RAG 问答
9. 章节摘要
10. 全书分层总结
```

## 阶段目标与最终目标验收定义

阶段实现目标完成时，应满足：

> 用户无需生成式模型，即可对当前书和整个书库执行可靠的全文/语义混合搜索，查看相似段落和书籍，获得带证据的固定体系标签建议，并通过结果稳定跳回 EPUB 原文。

最终目标完成时，应满足：

> 用户可以选择内置、本地或第三方模型，在可靠检索基础上进行带原文引用的问答，并以可暂停、可恢复、可追溯的分层流程生成章节和全书总结；生成能力失效时，阅读、全文搜索和智能检索仍保持可用。
